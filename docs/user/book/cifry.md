# Откуда берутся цифры

Справочник по всем денежным величинам программы. Каждая формула написана один
раз — остальные главы ссылаются сюда. Если два экрана показывают разные числа,
ответ почти всегда здесь.

---

## Главное правило: одна цифра — один источник {: #odna-cifra }

В программе нет двух мест, где одно и то же считается по-разному. Например,
«сколько денег в ящике» — это **баланс счёта «Касса»**, и смена не считает его
заново, а берёт готовым. Так сделано специально: две независимые формулы рано
или поздно расходятся, и никто не знает, какая права.

---

## Продажа: из чего складывается сумма чека {: #summa-cheka }

По каждой строке чека:

```
Подытог строки  = Количество × Цена за единицу
Налог строки    = Подытог × Ставка налога ÷ 100
Итого по строке = Подытог + Налог − Скидка
```

По всему чеку:

```
Подытог чека = сумма подытогов всех строк
Налог чека   = сумма налогов всех строк
К оплате     = Подытог + Налог − Общая скидка + Общая наценка
```

Округление — до копейки, **в большую сторону при ровной половине**
(0,005 → 0,01). Цена за единицу хранится с точностью до 4 знаков — это нужно
для весового товара; сами деньги всегда 2 знака.

!!! note "Почему цена 4 знака, а деньги 2"
    Товар по 19,99 за килограмм, продали 0,5 кг. Если округлять цену до копеек
    на каждом шаге, экран покажет 9,99, а списать может 10,00. Поэтому цена
    точнее, а округляется только итог.

## Оплата: чем закрыт чек {: #tendery }

Один чек можно закрыть несколькими способами сразу — например,
**26 наличными + 10 картой DC + 10 Эсхата + 4 в долг**. Каждая часть
записывается отдельной строкой оплаты.

Правила:

- Сумма всех частей должна **точно** совпадать с итогом чека, до копейки.
- Долг можно указать **только один раз** — у клиента один баланс, а не
  несколько.
- Для долга обязателен клиент.
- Для карты обязателен банк (DC, Эсхата, Alif).

Именно строки оплаты — источник всех денежных цифр: остаток кассы, итоги
смены, сводка по продажам, фильтр по способу оплаты, счета на странице
«Деньги». Колонка «способ оплаты» в списке продаж показывает **самую крупную**
часть и служит только для отображения.

!!! warning "Смешанный чек в списке продаж"
    Чек на 50 сомони, где 46 наличными и 4 в долг, в колонке «Оплата»
    показывается как **Наличные** — это самая большая часть. Долг при этом
    существует и виден в карточке клиента. Не считайте по этой колонке деньги.

## Сколько наличных в ящике {: #ostatok-kassy }

Баланс счёта «Касса» — единственный ответ. Он **не хранится, а считается
заново при каждом открытии страницы** из четырёх источников:

```
Остаток счёта = Начальный остаток
              + Внесения − Изъятия          (записанные вручную движения)
              + Продажи, оплаченные этим способом
              + Оплаты долга этим способом
              − Возвраты, выданные этим способом
```

Куда попадают деньги от продажи:

| Оплата | Куда попадает |
|---|---|
| Наличные | счёт **Касса** |
| Карта DC / Эсхата / Alif | счёт соответствующего банка |
| Карта банка, для которого счёта нет | **Банк (прочее)** |
| Мобильный платёж | **Банк (прочее)** |
| В долг | **никуда** — товар ушёл, деньги нет |

## Смена: «Ожидается в кассе» {: #ozhidaetsya }

Смена — это **промежуток времени**, а не отдельный кошелёк. Панель показывает,
что произошло с ящиком за этот промежуток:

```
На начало
+ Продажи наличными
+ Оплата долга наличными
− Возвраты наличными
+ Внесения в кассу
− Изъятия из кассы
± Из прошлых смен
= Ожидается в кассе
```

**«Ожидается в кассе» берётся из баланса счёта «Касса»**, а не складывается из
строк выше. Строки объясняют сумму; если они её не объясняют полностью,
остаток выносится в отдельную строку **«Из прошлых смен»** — вместо того чтобы
молча разойтись с денежной страницей.

Подробный разбор каждой строки — в главе [Смена](kassa/smena.md).

## Что в ящик не попадает {: #ne-v-yashchike }

Три вида денег входят в **выручку смены**, но их **нет в ящике**:

| Что | Где деньги на самом деле |
|---|---|
| Оплата картой | на счёте банка |
| Мобильный платёж | на счёте «Банк (прочее)» |
| Продажа в долг | у клиента, ещё не получены |

Прибавлять их к пересчёту наличных нельзя. Программа предупредит, если разница
при закрытии смены окажется ровно равна одной из этих сумм.

## Выручка {: #vyruchka }

Слово «выручка» в программе означает две разные вещи. Это не ошибка — это
разные вопросы.

**Выручка смены** (панель смены, «Итого выручка»):

```
Наличные + Карта + Мобильный + В долг
```

Отвечает на вопрос «на сколько наторговали за смену», независимо от того, где
сейчас деньги. Возвраты и оплаты долга сюда **не входят** — они показаны
отдельным блоком «Прочие движения денег», потому что долг был продан раньше, а
возврат уменьшает прошлую продажу.

**Выручка в отчётах** (Дашборд, Аналитика):

```
Оборот (сумма чеков) − Возвраты
```

Отвечает на вопрос «сколько заработали за период». Отменённые чеки не
считаются вовсе.

!!! example "Пример расхождения"
    За день продали на 1 000. Вечером клиент вернул товар на 200 по чеку той же
    смены.

    - Смена: **Итого выручка 1 000**, отдельной строкой «Возврат (наличные) −200».
    - Аналитика: **Выручка 800** (оборот 1 000 − возвраты 200).

    Оба числа верны, вопросы разные.

## Прибыль {: #pribyl }

```
Прибыль = Выручка (за вычетом возвратов) − Себестоимость проданного
```

**Себестоимость проданного** берётся не из текущей карточки товара, а из
цены, зафиксированной **в момент продажи** для каждой строки чека. Если
завтра поставщик поднимет цену, прибыль за вчера не изменится.

Возвращённые единицы вычитаются из обеих частей: и из выручки, и из
себестоимости.

Списания в прибыль **не входят** — они показываются отдельной величиной
«Списано за период» рядом с неизменной прибылью. Так видно и то, сколько
заработали на торговле, и то, сколько потеряли на порче.

```
Прибыль после списаний = Прибыль − Себестоимость списанного
```

## Возврат и долг {: #vozvrat-i-dolg }

Возврат **сначала гасит долг клиента по этому чеку**, и только остаток
выдаётся деньгами:

```
Ушло из кассы = Сумма возврата − Сколько списалось с долга
```

!!! example "Почему так"
    Чек на 50: клиент заплатил 46 наличными, 4 остались в долг. Клиент
    возвращает весь товар.

    - **Правильно:** 4 списываются с долга, 46 выдаются деньгами. Магазин
      вернул ровно то, что получил.
    - **Неправильно** (так было раньше): долг обнуляется *и* 50 выдаются из
      кассы. Магазин отдал на 4 больше, чем взял.

Сумма возврата (стоимость возвращённого товара) при этом не меняется — на неё
уменьшается оборот и по ней считается, сколько ещё можно вернуть по чеку.

## Долг клиента {: #dolg }

Баланс клиента — сумма всех записей в его истории:

| Запись | Знак | Когда появляется |
|---|---|---|
| Продажа в долг | **+** вся сумма чека | продажа с частью «в долг» |
| Оплата при продаже | **−** | что заплатили сразу, на кассе |
| Оплата долга | **−** | клиент принёс деньги позже |
| Возврат | **−** | вернул товар |
| Аннулирование | **−** | чек аннулирован целиком |

Положительный баланс = клиент должен магазину.

!!! warning "«Оплата при продаже» и «Оплата долга» — разные вещи"
    Обе уменьшают долг на одну и ту же сумму, но означают разное:

    - **Оплата при продаже** — деньги, отданные у прилавка в момент покупки.
      Они уже посчитаны как оплата чека.
    - **Оплата долга** — деньги, принесённые позже, отдельным приходом.

    Если считать первое вторым, одни и те же деньги попадут в отчёт дважды:
    как продажа в тот день и как погашение долга. Именно такая ошибка однажды
    задвоила 1 066,64 по 46 чекам.

## Стоимость склада {: #sklad }

```
Стоимость склада = Σ (Остаток товара × Себестоимость)
```

Себестоимость берётся из партий: товар, купленный раньше, продаётся первым
(FIFO). Поэтому при продаже списывается цена **той партии, из которой ушёл
товар**, а не средняя и не последняя.

Списание работает так же: акт списания забирает себестоимость из тех же
партий и запоминает её навсегда — партии завтра может уже не быть.

## Закупки {: #zakupki }

Отчёт по закупкам считается по **фактически принятому** товару:

```
Потрачено = Σ (Принятое количество × Цена закупки)
```

Заказ, который создан и отправлен, но ещё не принят на склад, **ничего не
стоит** и в отчёт не входит. Такие заказы вынесены во вкладку «Заказано, но
не пришло».

---

## Часовой пояс: когда заканчивается день {: #chasovoy-poyas }

Отчёты закрывают день по **часовому поясу компании**, а не по времени сервера.
Продажа в 23:30 попадёт в тот день, который был по местным часам, а не по
UTC. Это относится ко всем периодам: «сегодня», «7 дней», «30 дней».

## Что нельзя изменить задним числом {: #nelzya-izmenit }

| Действие | Можно отменить? |
|---|---|
| Движение денег (внесение, изъятие, перевод) | Нет — записывается встречное движение, история сохраняется |
| Закрытая смена | Нет — итоги заморожены в момент закрытия |
| Аннулированный чек | Нет, это конечное состояние |
| Полностью возвращённый чек | Нет |
| Черновик закупки | Да, можно удалить |
| Отправленная закупка | Только отменить, не удалить |

Причина одна: по этим цифрам людей уже оценили. Задним числом меняются не
данные, а только то, что дописывается сверху.
